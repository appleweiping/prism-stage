# Research and design decisions

Prism Stage is an interaction and creative-workflow project. It combines established hand tracking, segmentation, procedural graphics, and rigid-body simulation. It does not introduce a new vision model or claim state-of-the-art tracking, matting, dance assessment, or physical reconstruction.

The following nine repositories were examined through their README, implementation entry points, and available license files on **10 September 2026**. Observations below describe that inspection, not a controlled performance comparison. Linked default branches may change. No source code, demonstration video, choreography, music, or model weights from these nine projects are bundled in Prism Stage. Runtime dependencies and the two Google models are documented separately in [Third-party notices](../THIRD_PARTY_NOTICES.md).

## What these references changed

1. **The unit of creative work is a take.** Recorded input survives changes to palette, material, and framing. A video-only result cannot support that workflow.
2. **Gesture stability belongs between inference and interaction.** Models return observations; an application still needs association, filtering, hysteresis, and loss handling. Handedness classification confidence is not a gesture-confidence value.
3. **Choose a task-specific representation.** Ribbons and physics keep processed hand observations. The portal keeps person-probability masks. Neither requires retaining the original footage inside the project file.
4. **Keep the product's promises measurable.** Exported media must decode, saves must reopen, a lost hand must release its object, and scene switches must dispose resources. “Best” is not a useful substitute for these checks.
5. **Expose the approximation.** Depth is an artistic mapping; the mask has limited spatial detail; tracked hand identity can fail during severe occlusion. A smooth demo is not proof of model accuracy on every person or camera.

## Technical references used in implementation

- [MediaPipe Hand Landmarker guide](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker): model outputs, VIDEO mode, and tracking thresholds.
- [MediaPipe Image Segmenter guide](https://developers.google.com/edge/mediapipe/solutions/vision/image_segmenter): confidence masks and the landscape selfie model.
- [Official MediaPipe worker example](https://github.com/google-ai-edge/mediapipe-samples-web/blob/main/src/workers/image-segmenter.worker.ts): browser worker deployment considerations. Prism Stage's worker and protocol are independently implemented.
- [Rapier JavaScript user guide](https://rapier.rs/docs/user_guides/javascript/getting_started_js/): rigid bodies, colliders, and simulation ownership.
- [MediaRecorder format detection](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/isTypeSupported_static): feature-detect actual recording formats rather than renaming a container.

These references explain engineering choices. They do not constitute a benchmark or an endorsement by the original authors.
